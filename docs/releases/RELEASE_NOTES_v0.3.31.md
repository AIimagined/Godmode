# Godmode v0.3.31

## Added

- `godmode authorize stage` now opens a native password dialog when it runs without a terminal, so a refused call can be approved from the chat prompt with `! "<plugin>/bin/godmode" authorize stage --from-last-refusal` instead of a separate terminal window. The dialog is the Windows credential prompt, a macOS dialog with a hidden answer, or zenity/kdialog on a Linux desktop; it shows the exact command, that the approval is spent once, and its expiry. The password goes from the dialog to the approval check in the same process, never through the chat, a command line or the environment, and the dialog path accepts no password from standard input. Cancel stages nothing, a wrong password is refused as before, and a machine with no dialog keeps the separate-terminal message.
- `godmode doctor --repair-fork --as-operator` (the operator's password) repairs an archive left with two records at the same sequence at its tip. It keeps the record the chain anchor names (the earliest one when no anchor names either), moves the others into a quarantine folder beside the archive's records rather than deleting them, records the repair as its own entry, and re-verifies the chain. Any other shape - a duplicate below the tip, siblings that do not share one predecessor, a record that fails its own hash - is refused and left untouched.
- `godmode evals --refresh` rewrites every committed eval snapshot (routing, routing-stability, charter, ranking) in one command, skipping any fixture whose content is already current.
- The release check (`godmode precheck --preflight`) now reports test-suite growth since the previous release tag - how many `tests/test_*.py` modules and `def test_` functions were added. Growth over 10% is an informational note in the default advise mode, and a real finding in strict mode; with no previous tag, it reports nothing.
- The publication and name-reference quality checks now report on what changed instead of the whole tree by default: `--filter added|file|all` picks which findings count, and `--fail-level harm|error|warning` picks which of those fail the run. A finding on a line your change did not touch is labelled pre-existing and never blocks it; the release check and CI keep the full-tree, fail-on-anything behavior. The accepted-reference list is now keyed to a reference's exact text rather than its line number, so an unrelated edit that moves the line no longer breaks an accepted entry.

## Changed

- An agent's own shell call can no longer start an approval: `godmode authorize stage`, `setup`, `grant` and `issue` are refused in every mode - attended, unattended, auto and observe - in any launcher form (the bare launcher, `python scripts/godmode.py`, a quoted path, a PowerShell call, or inside a compound command or a `bash -c` payload), and no staged approval opens them. These verbs raise your password dialog, and a prompt raised on an agent's behalf is one you learn to click through. The refusal names the remedy: type the same command yourself with a leading `!`. `godmode authorize request` and `authorize requests` stay available to agents.
- `lessons approve` no longer trusts the agent id alone to tell the approver from the promoter. Promotions and approvals now record the writing process as the operating system reports it (pid, parent chain, the agent host or terminal driving it, and any declared session), and an approval is refused when both resolve to the same process, session, parent or driving program, or when one process started the other - so renaming `GODMODE_AGENT_ID` between the two steps no longer passes. A promotion recorded before this change must be re-minted before it can be approved. THREAT-MODEL.md states the remaining boundary: every process belongs to one local user.
- A command that changes directory before a read, such as `cd src && git log`, is now decided on the fast path instead of starting the full gate. Every other part of the command is still judged on its own.
- `scripts/dev/ci_local.py` now runs the committed workflow's Linux jobs through a local Actions runner when one, and Docker, are both found on PATH - real containers instead of this repository's own approximation of the gate list, so a green local run is a stronger signal that the push will be green on GitHub too. Without both of those on PATH, or with `--native`, it falls back to running the gate list as before. Either way it prints which path it took. Windows and macOS legs are never run through a container; they only ever run natively, on a machine of that OS.
- A repeat edit of a file the full gate already cleared in the same session is now allowed on the fast path, without starting a second process. The fast path allows it only while nothing those checks read has changed: protected paths, settings files, frozen-region markers, the plan, the scope fence, the design boundary, repeated-reversal evidence and the project's own records all send the edit back to the full gate, which decides it exactly as before.
- A write into Godmode's own install directory or into the private bytecode cache its hook launchers use now needs your approval the same way a change to Godmode's settings does, since a file planted there runs inside the gate.
- Hooks keep their byte-code in a private cache under the Godmode application home instead of recompiling the runtime on every firing, and the session hook now loads through that cache too. Hooks stay isolated from the environment (`-I`), and nothing is written beside the plugin. On a governed project this roughly halves the time hooks add to an ordinary turn (measured 8.8 s to 4.5 s for the turn in `scripts/dev/measure_turn_cost.py`).
- Godmode adds far less text to an ordinary turn. Outside strict mode:
  - Stop runs only the loop, stall and unsupported-claim checks. The other end-of-turn checks run under `godmode config mode strict`.
  - Stop notices reach the model once, at the next prompt (on Grok, the next allowed tool call), instead of also appearing as an operator message.
  - The doctrine and red-flags text rides a project's first session brief only. After that, `godmode docs --emit-rules` writes it on demand.
  - The session brief keeps a single open-obligations count. `godmode resume` now also shows the ledger, laws and next actions.
  - Post-edit quality findings give one summary line per session. `godmode quality --format editor` lists them all.
  - Strict mode keeps the full output.
- Running two different Godmode versions as writers against the same project archive at once is not safe - a version mismatch can now be named instead of surfacing as plain contention, but the mismatch itself is still a real risk until every host writing that archive is upgraded to the same version.
- The `godmode` command line no longer accepts abbreviated long options (`--as-op` for `--as-operator`); write each option in full. An operator-only verb run under `tmux`, `screen`, `socat`, `ssh -t` or `setsid`, or with an abbreviated `--as-operator`, now needs your approval like one run under `script` or `winpty`.
- `godmode adopt --confirm` and `godmode doctor --repair-fork` now refuse unless run with `--as-operator`: relinking an archive to a new identity and choosing which of two forked records survives are the operator's decisions, verified by the password from `authorize setup` (via `--password-stdin` or a prompt). With no password configured they are refused with the `godmode authorize setup` remedy; there is no y/N fallback.
- README now states where the plugin's `godmode` launcher lives (`bin/godmode.cmd` on Windows, `bin/godmode` on macOS/Linux) and how to call it or add it to PATH, since a plugin install does not put it there itself.
- Project skills change in any session. When nobody is watching, each change - an edit or write, `skill forge`, `skill retire`, `skill restore` - is recorded, reported once per session ("skills/<name> changed (<how>) in an unattended session - review the diff") and listed by `godmode status`. To lock a skill, list it in `.godmode-boundaries.json` (`skills/<name>/**` under `ui.declared`): every one of those writers is then refused in every session, and one change passes only with the password: staged as the refusal shows, or a skill command run `--as-operator`. `skill forge` now accepts `--as-operator`.
- The subprocess-heaviest test modules (the ones that shell out to the CLI
  repeatedly and together account for several minutes of suite time) now run
  only in the release check, not a routine local pass. `godmode precheck
  --preflight` still runs every one of them; nothing security-related (gate,
  authorize, guard coverage) moved.
- An `ask_only` policy no longer turns an R2/R3 ask into an allow while the session is unattended (`GODMODE_ATTENDED=0`, `CI`, or a no-human-ask permission mode). The call follows the unattended rules every other path follows: it asks where a person can answer, and is refused where the host answers its own asks. Attended sessions keep the focused posture unchanged.
  - Standing lessons are stricter for an actor nobody is watching. Unattended, a standing lesson cannot be rewritten, retired, amended or expunged; attended, the change proceeds and its diff is shown. `skill retire` archives rather than deletes, and the new `skill restore --seq <retirement seq>` puts a retired skill back.
- An installed Godmode plugin now asks before (or, on hosts without an ask prompt, blocks) force-push, history rewrite, deletes outside the project, and releases or publishes in projects where `godmode init` was never run; turn this off machine-wide with `godmode config set uninitialized off`, or for one repository with `godmode config set uninitialized off --repo`. Ordinary commands in those projects stay silent and fast, nothing is recorded, and no archive is created. The session is told at its start (on Grok, with its first tool call) that only harm-class commands are guarded until `godmode init`.
- `godmode explain-context` is renamed to `godmode context why` (call it with no `--about` for the same output as before). The old name still runs for this release: it prints a one-line deprecation note naming `context why` to stderr, then runs exactly what it always ran, before being removed in a later release.
- In an initialized project, a command that weakens Godmode's own protection now needs your approval the same way a push or release does: `godmode config set uninitialized off` (machine-wide or `--repo`), `godmode config mode advise`, a `git config` write of a `godmode.*` key, and any write to the machine-wide `godmode-settings.json`. The host asks when you are present and the command is refused, with a staged-approval remedy, when nobody is. Reading a setting and moving a switch to its stricter value (`guard`, `strict`) stay free.

## Fixed

- `godmode adopt --confirm` now relinks an archive that travelled with a moved or copied checkout. Such a checkout resolves a new identity while its archive still carries the old one, so every write refused, and adopt refused too because the archive already held records. Adopt now previews the relink, and with `--confirm --as-operator` (the operator's password) verifies the chain, records the new identity while keeping the old one accepted for the records it wrote, and records the relink in the archive. The identity check on every other write is unchanged.
- The approval password dialog now shows control, bidirectional and zero-width characters in a staged command as visible escapes, so the command shown is the command approved. A command too long for the dialog to show in full (600 characters as shown) is refused with that limit named, instead of being cut off.
- `lessons approve` now refuses an approval whose process shares any ancestor with the promoting process below the system init or desktop shell, not only its parent, and skips perl, ruby, node, git, make and find when finding the driving program. The threat model now states plainly that on macOS only the parent process is compared.
- Writers under heavy load are no longer refused with "archive is busy". The archive's write lock used to be won by whichever waiting writer happened to retry first, so with many hooks writing at once a writer could lose every retry until its deadline passed. Writers now take a place in line and enter the lock in arrival order, so each waits only for the writers ahead of it; a writer that dies in line is skipped once its process is gone, and a live writer that holds the lock is still waited on, never overtaken.
- Concurrent writers can no longer fork the archive with two records at the same sequence. A hook process that had cached its view of the archive could, when the head hint did not validate (a writer interrupted between sealing its record and updating the hint), read the chain tail from that stale view and seal a second record at a sequence already on disk - after which every later write refused with "chain broken". The tail is now always re-read from disk under the write lock, every sequence is claimed exclusively before its record is written (a second writer of the same sequence re-reads the tail and retries instead of forking), and the fallback lock used where kernel locking is unavailable is taken over only from a holder that is provably dead, never from one that is merely slow.
- `godmode authorize` run from an agent's tool call is now refused unless its verb is written out literally as `request`, `requests` or `deny`: a verb built when the line runs (`$(echo stage)`, `${v:-stage}`, `$v`, PowerShell's `('st'+'age')` or `@args`) and any `xargs ... godmode authorize` can open the operator's password prompt and no longer pass.
- A branch's declared role (`godmode branches --record --role ...`) now stays in effect for the life of the archive. It used to be read through a bounded window (the newest 500 matching records), so a role declared early in a long-lived project could silently revert to the branch's name-based default once 500 later branch-topology records had accumulated.
- `godmode changelog merge` now writes CHANGELOG.md with LF line endings on every platform, instead of CRLF on Windows.
- The subprocess-heavy test modules were never actually running in the checks that gate `main` - the workflow enabled them by convention but never set the environment variable that turns them on, so they silently skipped on every push and pull request. Both jobs that gate `main` now run them.
- Unrecorded claims parked for the next prompt are no longer lost when a subagent and its parent session, or two sessions on one project, finish at the same time. Each park is written under the archive lock, sentences from the same session accumulate, and another session's park is kept for that session.
- A claim whose cited check just failed, or whose held-back check ran red, now reports the downgrade honestly: `claim --verify` keeps the grade you asked for on record, reports the grade it actually earned, and exits nonzero - instead of silently rewriting the request and exiting clean.
- A malformed command line (an unrecognized value, a missing required flag, an out-of-range option) now reports `{"error": "UsageError", "message": ...}` on stderr with exit 2, the same shape and stream every other CLI failure uses - instead of plain usage text that ignored `--json`.
- An approval staged for an edit the design boundary refuses is now spent only when every other check allows the edit. Before, a later refusal (a scope fence, a frozen region, plan-first) spent the approval with no edit made.
- An edit refused by the design boundary in `.godmode-boundaries.json` can now be approved: `authorize stage --operation "edit file <path>"` accepts it instead of answering that read-only inspection needs no capability, and the approval is spent once by the next Edit or Write of that path, while `skill forge`, `skill retire` and `skill restore` on a locked skill take their own approval (`forge skill <name>`, `retire skill <name>`, `restore skill <name>`), so an approval for one file never unlocks a whole-skill command. The refusal prints that command with the plugin's own launcher, ready to run.
- A relative path is now judged from the directory an earlier `cd`, `pushd`, `popd` or `Set-Location` in the same command moved to. `cd .git && echo x >> config` is asked about as a write to the repository config, a write after a directory change the command cannot resolve is asked about, and returning to the project root first stays allowed.
- The end-of-turn completion check no longer skips a whole sentence because it contains a quotation: only the quoted words are set aside, wording a reply styles as its own proposal (`*"..."*`) is still checked, and apostrophes inside words are never mistaken for quote marks.
- The evidence-pipe note no longer fires on a run whose output was saved to a file first and filtered afterwards (`cmd > run.log 2>&1; grep ... run.log | tail`), which is the very remedy the note recommends; output sent to the null device, or piped straight into a filter, still draws it.
- On platforms without kernel file locking, the archive write lock can no longer be wedged for good by a holder that is alive but hung: a lock older than 30 minutes is taken over. The lock now records its host, and a lock written on another host is not taken over on the strength of a local process lookup before then.
- The gate no longer reads a disguised command name as an unknown read. A command name spelled with non-ASCII lookalike letters (`gіt` with a Cyrillic `і`) is asked about as an unknown command. PowerShell's `& $cmd`, `. $script` and `& (expression)`, `Start-Process`, and a Bash `$cmd` or `${x:-git}` command word are read as the command they run, or judged opaque (an ask) when the text cannot name it; `& (Get-Command git)`, `$'git'`, a dot-sourced script and a `winpty`/`script -c`/`unbuffer` wrapper are read as what they run. Quoting a flag or subcommand (`git "push" "--force"`) no longer lowers a forced push to an ask. Running an `--as-operator` verb under a pseudo-terminal wrapper now asks like any other change to Godmode's own protection.
  - On Windows, a shell tool that does not say which shell it runs is now also read as cmd.exe, so `echo 'a & git push --force'` is refused there; the stricter reading still wins.
- Every category floor in the gate's tier table is now pinned by a test that proves the floor, not the fallback tier, decides the verdict. Twelve floors used to equal the fallback, so removing one changed nothing a test could see; the one floor no command could reach has been removed and now takes the fallback, with no change in any verdict.
- `time -f FORMAT` and `time -o FILE` in front of an unrecognised command after `&&`, `;` or `||` no longer hide that command: the option's value is read with its flag, so `ls && time -f %e ./script.sh` asks like `ls && ./script.sh` does. `time -o FILE` is also read as a write to FILE.
- Grok now receives a real permission prompt instead of an automatic deny for a recoverable refusal, and its quality/untrusted-content findings after a tool call now actually reach the model - Grok's stdin envelope is camelCase, and the post-tool-use hook was reading only the Claude-shaped snake_case field names, so it silently did nothing on every real Grok call. The reach table's Grok row reports both as supported by Grok's current documentation, pending a live confirmation.
- In a project where `godmode init` was never run, a write that lands in the repository's git config or the machine-wide settings file is now asked about however its path is spelled: a `.` or `..` segment, a `cd` earlier in the same command, or a glob. A redirect whose target is a glob is no longer treated as an ordinary working-file write.
- `godmode hooks status` now leads with whether the project is initialized, whether the hook is wired, whether it has ever been invoked, and the date and version of its last recorded deny - plus the one command that advances to the next state. An uninitialized project now reads `not initialized: run godmode init` instead of silently reporting a partial grade as if nothing were missing, and the `version` field always names the running CLI's own version instead of the honest-but-useless `unknown`.
- A record served from the archive's on-disk read index now gets the same project-identity check a freshly-read record already gets; an accelerated read used to skip it entirely, so whether a foreign record was caught depended on how much of the archive the index happened to cover. A moved or copied checkout hitting the append-side identity check now gets a clear message naming both identities, and its own `adopt()`-recorded identity, instead of a bare "does not match".
- The lesson-pin check that caps a claim from grading `verified` while an active lesson pins its surface now reads every lesson in the archive, instead of only the newest 200. A pin recorded early in a long-lived project used to stop capping claims silently once enough newer, unrelated lessons had accumulated past that window.
- A write-lock timeout now names a genuine version mismatch instead of reporting plain contention. Two different Godmode runtime versions writing the same archive used to see "archive is busy" either way; the lock now records the owning runtime version, and a timed-out writer reads it back - a different version is refused loudly by name, telling an operator to run the same version everywhere that writes the archive, while ordinary same-version contention still reports the busy retry it always did.
- A child process that crosses the memory cap during preflight and cannot be killed is no longer reported as killed for memory. The kill is retried, and when it still fails the run reports that the kill failed and keeps watching the child.
- Operator asks are now minted from the operator's own typed words only: a subagent's hand-back report, even one delivered behind the host's own delivery notice or a system-reminder block, is never recorded as an ask; pasted terminal output is stripped out of a prompt before its ask is derived, so a prompt that is only a paste records no ask and a prompt that mixes operator words with a paste records the operator's words alone.
- `tee` and PowerShell's `Tee-Object` are now judged as the writes they are: `cat notes | tee /etc/hosts` asks, as a redirect to the same file would, while `tee` into the working tree stays free. `xargs` is judged by the command it runs. `nl` and `column` now take the fast path as plain reads.
  - A claim cited on a pipeline that ends in `tee`, `nl`, `column`, `rev` or a PowerShell object cmdlet (`Select-Object`, `Sort-Object`, `Measure-Object`, `Out-String` and the like) is graded on that filter's exit code, not the run's, so it is no longer graded verified. A pipeline ending in `xargs <command>` is graded on that command.
- `godmode` preflight now polls the memory of the test-suite processes it spawns (each shard and the designated suite) and kills one that crosses a configurable cap (4096 MB by default, `GODMODE_CHILD_MEMORY_LIMIT_MB` to change it), reporting the peak RSS observed - instead of letting a runaway child grow unbounded until the OS or the hour-long timeout stopped it with no memory figure in the finding.
- Preflight's memory-cap kill no longer reports a child process as killed for memory when the child had already exited on its own between the memory sample and the kill attempt.
- `precheck --preflight` no longer risks holding the archive's write lock for the whole run. Its closing attestation now warms the enforce-lesson sidecar first, from an unlocked read, the same way `godmode doctor` already does - so the write lock the attestation takes is scoped to that one write, and other writers (hooks included) are never blocked behind a preflight run's own backlog catch-up.
- `quality/checks/prepublication.py` used to print only the first 10 findings per group while its summary line counted all of them, so a red run could hide most of what was wrong. It now names how many of the true count are shown, and a truncated group's report says so directly ("re-run with --all to see every one"); pass `--all` to print every finding. A new `--baseline PATH` diff mode grades only findings absent from a stored baseline (write one with `--baseline PATH --write-baseline`), for accepting a known backlog without going green on it silently.
- The ranking eval snapshot no longer depends on git commit time or commit order: the same project content always produces the identical fixture, no matter how it was committed.
- The routing-stability eval snapshot now always writes plain LF line endings and skips the write entirely when its content has not changed, so simply running the eval suite no longer dirties a clean checkout with a line-ending-only change.
- `godmode status remaining --digest` (and any digest built from `session_digest`) now refuses a `--session` id that matches no session in the archive, instead of silently falling back to lifetime spend and counts as though no session had been given.
- `godmode status` and the once-per-session report no longer forget a project skill changed in an unattended session once more than 500 later skill changes are recorded; the whole archive is read.
- Progress-log lines that open with a status label (`Done:`, `Landed:`, `In progress:`, `Pending:`, `Status:`) no longer draw the "claim-shaped statement" note at the end of a turn; a measured claim in ordinary prose still does, and the completion check still judges every line.
- An edit refused by a design boundary (or any other per-file check that ends in a deny) now leaves one refusal on the record, the same as a refused command, so `authorize stage --from-last-refusal` and the refusal history see it; an edit that only asks still writes none.
- In a project where `godmode init` was never run, a harm-class command spelled through shell quoting (`git "pu"$'sh' -f`) is now checked like its plain spelling instead of passing silently.
- In a project where `godmode init` was never run, a command whose program or git verb is only built when it runs (PowerShell's `& ('gi'+'t') push -f`, `$cmd push`, `git $(printf pu)sh`) is now asked about instead of allowed silently.
- Uninstalling from a project no longer wipes out another tool's entries in a shared hooks file. Antigravity's `.agents/hooks.json` holds one key per tool; removal now strips only Godmode's own key and leaves the rest of the file - and the file itself - in place, deleting it only when Godmode's key was the last one there.
- `hooks wire --host codex|opencode|antigravity` no longer needs `--force` for an ordinary version update. It now recognizes its own prior write (a digest recorded alongside it) and updates in place, the same leniency `hooks wire --all` already gave these files; a real conflict - a hand edit, or content from something other than this writer - still needs `--force`.
- `lessons approve` no longer refuses an operator who approves from another tab of the same terminal or IDE the agent runs in: terminal emulators, IDEs, multiplexers and remote-login daemons are treated like the desktop shell, shared by separate actors, while an ancestor such as the agent host itself still ties the two.
- Two writers waiting on an abandoned fallback archive lock can no longer both take it over: the takeover is made by one writer at a time and only while the lock file is still the one judged abandoned, so a waiter that arrives late leaves the new holder's lock in place.
- Running the console module directly (`python -m godmode_runtime.godmode_console authorize stage ...` or `python .../godmode_console.py authorize ...`) is now refused to an agent exactly like the `godmode` launcher, so it cannot open the operator's password dialog.
- `cd -` is now followed back to the directory the previous change left, so `cd sub && cd - && echo x >> notes.txt` is judged as a write in the project root instead of asking.
- A staged design approval is no longer spent by an edit a declared tool gate then stops, and a patch that touches several locked files is refused before any of its approvals is spent when one of them could not be; the edit's approvals are spent together only once every check has allowed it.
- A redirect written without a space before it (`echo x>>config`, `echo "x">>config`) is now read as a write when an earlier `cd` in the same command moved the directory, so `cd .git; echo x>>config` asks like its spaced spelling.
- A directory change whose target comes from a command substitution (`cd "$(printf .git)"`, `cd "$(pwd)/.git"`) is now read as a directory the command cannot resolve, so a write after it asks instead of passing as a write inside the project.
- In a project where `godmode init` was never run, a write to the repository config from a shell already sitting in `.git` (a directory an earlier call moved to) is now asked about; relative paths are judged from the call's own directory as well as the project root.
- In a project where `godmode init` was never run, a write to the repository config after a directory change written with flags (`cd -P .git`, `cd -- .git`, `Set-Location -Path .git`, `Set-Location -Path:.git`) is now asked about; the directory is read from the first word that is not a flag, and a flag that cannot be read makes the directory unknown.
- In a project where `godmode init` was never run, a write after a directory change and a return (`cd .git && cd .. && echo x >> config`, `pushd .git && popd`) is no longer asked about: the guard follows one current directory through `cd`, `cd -`, `pushd` and `popd`, runs `&&` and `||` the way the shell does, and still asks when a change may not have happened or sits where it cannot be placed (a quoted string, a heredoc, a subshell, `eval`).
- In a project where `godmode init` was never run, a harm-class verb, flag or program completed by an expansion (`git reset --ha$@rd`, `g''it p${_}ush`, `gh rel$@ease`, `r$@m -rf`) is now asked about, and a command that reads as harm-class once its expansions come out empty (`npm pub$@lish`) is judged as that command.
- In a project where `godmode init` was never run, a write to the repository config through a symlink, a junction or a hard link (`ln -s .git g` then `printf x >> g/config`) is now asked about; a path is judged by what the filesystem resolves it to, and a link made in the same command makes any path that could name the file count.
- In a project where `godmode init` was never run, a command that runs one of Godmode's own modules by name (`python -m godmode_runtime.godmode_console authorize stage`) is now handed to the classifier instead of passing the keyword screen.
- In a project where `godmode init` was never run, a command whose words are completed by a variable or a special parameter (`git pu$x -f`, `git pu$@sh -f`), a backtick substitution, a cmd `%x%`, or a brace or glob spliced into a word is now handed to the classifier instead of passing the keyword screen.
- An agent's command that passes `--as-operator` (however it is quoted or escaped) now needs your approval, and `godmode adopt --confirm` and `godmode doctor --repair-fork` run `--as-operator` now require the password from `godmode authorize setup`: with none set they are refused with that remedy instead of falling back to a y/N prompt a pseudo-terminal could answer.
- An operator-only verb run under a pseudo-terminal wrapper is now caught when the `--as-operator` flag is split by quotes or an escape (`--as-""operator`, `--as-\operator`), when the wrapper sits behind `timeout`, `env`, `nohup`, `nice` or `stdbuf`, and when the wrapper runs a command held in a variable or produced by a substitution (`tmux new -d "$C"`); each now needs your approval.
- The BSD `script` form (`script -q /dev/null godmode adopt --confirm --as-operator`) is now read with every word after the typescript file as the command it runs, so an operator-only verb under it asks like the `-c` form.
- A skill locked by a boundary that covers only some of its files (`skills/*/scripts/**`) or that lives under `.grok/skills` can now be unlocked the way its refusal says: `authorize stage --operation "retire skill <name>"` (and forge or restore) is accepted for it instead of being refused as a read.
