# Godmode v0.3.32

## Added

- Every claim records an `independence` tier derived from its citations (attested, recorded, external, self); a `cmd:` citation is archived with any secret-shaped token redacted; `claim --verify` refuses a citation that needs a shell and shows the two forms that work; `--cite-timeout` names the per-check timeout.
- `godmode roi --releases` prints one table per release tag range: password rounds staged and consumed, gate refusals by category, preflight runs with their minutes, and suite runs repeated for the same commit. `--json` gives the same rows as JSON, and each preflight attestation now records how long it took.
- An approval nobody answers within thirty minutes is recorded as a stall and announced once with a desktop notification naming what waits; the ask itself tells the agent to continue on files the pending call does not touch.
- Three skills front verbs that had none: `godmode-loop-warden` bounds a retry cycle and cuts it off at its cap, `godmode-budget` checks spend against declared ceilings from local records, and `godmode-ci` runs the push gates locally in CI's order; `godmode forget --rehydrate <seq>` brings a rotated record back into the hot tier as a new record citing the cold original, and the operator policy's `retention_days` sets per-kind retention down to a one-day floor.

## Changed

- In auto mode a local, reversible operation (a commit, a staged file, an in-tree delete, an inline script) is now asked about through the host instead of being refused outright; history, remote and release operations still refuse without a staged approval.
- The command line exits with one code per error class (privacy 3, authorization 4, identity 5, forge 6, corpus 7; refused or malformed stays 2) and answers an interrupt with 130 and a termination with 143; `remember --data` is accepted for `--value`; closing a request without citing the delivering commit records it as answered, not closed; `atlas law withdraw` takes back your own open proposal and frees its slot; `status` and `status --digest` use one trust rule, kept beside the supersession fold; a law whose cited evidence has left the archive is withheld from the law file and named as dormant; `law promote` needs the reviewer's own `--refuted-by`; a promotion citing a record the archive does not hold is refused; an approval from the session that promoted is refused; `law debrief --retire-failed` retires a law whose correction recurred after delivery; a skill whose eval suite validates its whole directory can now be ratified for its documents, with its graders still protected.
- A staged approval now lasts up to twelve hours instead of five minutes, so a push approved before a test suite or a CI run is still there when the push happens. It is still bound to the exact command, the repository, the worktree, the commit and the branch, and is spent once; a new commit invalidates it. The prompt and the dialog say so in hours and minutes.
- A staged approval now matches its command when it is run with a redirect into the working tree, a read-only filter after a pipe, or a read-only command beside it. A force flag, a redirect outside the tree, a pipe into a shell, a directory change or any other mutation beside it is still a mismatch.
- Superseding a record now also retires every lesson or decision whose evidence cites it, transitively; the cold registry carries a seal that `godmode doctor` checks after its content checks; `select(include_cold=True)` reads the rotated tier on request; `status` reports the highest sequence ever sealed; the unused opt-in "semantic decision" shape was retired, so a decision's data is its writer's own.

## Fixed

- The eval snapshots (routing, routing stability, charter, ranking) are refreshed for the reworded skills; `law compile` no longer raises when one of its own lessons cannot be served and instead leaves that law standing; the upstream diff help text reads as prose.
- Everyday git work runs without a password: a fast-forward pull, a switch, a stash, a local merge or tag, a worktree, a submodule checkout, `git init` and the non-destructive `git branch` flags are R1; `git branch -D` and `git rebase -i` refuse at R5. A delete inside the working tree asks like a file edit and one in the system temp directory runs; deletes elsewhere keep the R4 floor. An unrecognised command after `&&` or `;` runs and is recorded unless it carries a redirect, a delete or force flag, a network tool or a shell pipe. An interpreter payload is judged by what it executes, not by words inside its string literals. `gh` write verbs are named as external writes instead of unknown.
- A corrupt sidecar beside the archive (a claim echo, a parked measurement list) no longer degrades the whole hook event: each read falls back to a fresh state on its own and names the degradation once.
- A command approved with the password is no longer asked about a second time by the host: when the hook spends a staged approval it tells the host to allow that one call. Ordinary allows stay silent and ordinary asks stay asks.
- The push preflight runs its seconds-long checks first: the decision-table freshness check and the workflow gates now run before the test suite, and a red one stops the suite from starting. The report names the check that stopped it and the command that reproduces it, and the attestation reads `failed` rather than `incomplete`.
- The push preflight report names the tree it validated (HEAD or a working-tree snapshot) and lists every untracked path it did not validate as a finding; the closure check refuses a saved atlas index that never stored a file under its roots and names a budget trip on stderr; `bindings --write` reports every target whose install note could not be written; with `GODMODE_STATE_HOME` set, every state file of a git project lands under that home; the gate latency benchmark prints the noise band beside the p95.
- A read or a local test run is no longer refused with "the gate could not decide" while a suite or a second session holds the archive: when the full check runs past its deadline, the command is classified without the archive and allowed when it is read-only or local compute. Everything else still fails closed.
- The pre-commit hook regenerates and stages a stale `hooks/gate_table.json` instead of only refusing; the skill-impact floor is skill-wide, so a change must beat the best score any file of that skill recorded; several session transcripts merge into one timeline with duplicates counted and flaky checks named as conflicts; the host CI fire step reads a deny by its output, so a host that denies with a non-zero exit is not a broken launcher.
- The investigation skill names its orchestration gate: a fix is handed to another agent only with the incident's reproduction and retest list on record; the evidence skill's eval checks the flag it names; the memory-gardener and host-sync descriptions say what they exclude; the continuity skill's routing corpus covers resuming and handing off; `skill forge` refuses a destination outside `skills/` by name; a rejected skill change says when the skill was unscorable rather than merely worse; the fast gate's read-only floor is published for every shipped host directory; one closing-status set serves the forgetting pass and the chronicle; help and error text carry no internal review ids; the test-module bar and the rule for adding a module are written into the release checklist.
- The slow verbs are fast again on a large checkout: the near-duplicate scan compares symbols by bitmask instead of set arithmetic, the code atlas caches each file's extraction beside the archive, the loop detector's release history is cached under the tag list, `doctor` re-checks only the newest records for secret shapes (`godmode privacy` still scans everything), every CLI call pins the archive listing once per process, the scenario runner no longer loads at startup, and `evals --fast` skips the subprocess probes. Measured on this repository: metrics 377 s to under 10 s, minimality 278 s, loop 244 s, doctor 155 s, resume 14 s.
- The staging line a refusal prints now runs as pasted on bash and on PowerShell, quotes, dollar signs and newlines included, and stages exactly the refused command.
- A stop notice that already spent its once-per-session budget (a nag, a nudge, an idle-ask resurface) is never clipped out of the two-line stop message; a sentence that only repeats the hook's own earlier feedback no longer counts as a completion claim; a pre-tool refusal now reads rule, detail, checklist like a stop block; a hook whose archive read fails still answers each event in its own contract; the continuity brief never drops its newest record and names each record it drops; the stale gate-table refusal names the regenerate command.
- A shell's inline command (`bash -lc "…"`, `sh -xc "…"`, `cmd /c "…"`, `pwsh -Command "…"`) is scanned as the command it runs, so a forced push inside it still refuses; the string-literal rule that lets `python -c "print('git push --force')"` through applies to interpreters only.
