The full hook and the fast gate now decode a payload's stdin bytes the same way: a leading UTF-8 BOM, CRLF line endings, a trailing newline, trailing non-JSON data after the first object, and two concatenated JSON objects are all accepted by both, taking only the first complete object and ignoring anything after it. Previously the full hook decoded with a plain `json.loads`, which raises on a leading BOM (`Unexpected UTF-8 BOM`) and on anything after the first object (`Extra data`) - so a BOM-prefixed or trailing-data payload the reader (`hooks/godmode_stdin.read_first_json`) already tolerated was refused downstream with "Operation description cannot be empty" instead of being classified normally. A payload that is not JSON at all still fails closed for a protected pre-action call, unchanged.
