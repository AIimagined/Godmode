`quality/checks/version_payload_identity.py` checks whether the declared plugin version still names the payload a tag ships. It fails when `plugin.json` states the same version as the latest reachable `v*` tag while a commit after that tag touched shipped payload (`skills/`, `hooks/`, `scripts/`, `bin/`, `adapters/`, or a manifest); a docs-only commit after the tag does not trigger it. This is a release-time check run by hand immediately before cutting a tag (see `docs/RELEASE-CHECKLIST.md`), not part of the unit suite or CI - a sprint branch carries the last released version number while committing payload continuously until its release-prep bump, so it reads drift by design for most of a sprint.
